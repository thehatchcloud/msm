# Approved compatibility deviations

These are requirements for the Go port, not optional cleanup. A behavior not
listed here must be preserved or proposed for review before implementation.

| ID | Legacy behavior | Required Go behavior | Owner | Rationale |
|---|---|---|---|---|
| DEV-001 | Global and per-server config is interpreted through Bash `eval`; invocation is passed through a shell command string | Parse literal supported assignments and placeholders; execute Java/screen with argument vectors; reject executable shell syntax with a location and migration message | P03, P06 | Configuration must not be arbitrary code |
| DEV-002 | JAR and updater downloads use `wget --no-check-certificate` and do not verify a release manifest | Require verified TLS, deadlines, bounded responses, atomic staging, and available upstream hashes/signatures; the manager updater requires independently trusted release provenance | P07, P15 | Prevent interception and corrupted publication |
| DEV-003 | Delete prompts can still be awkward in noninteractive use and server deletion stops a running server after confirmation | Require a TTY confirmation or explicit noninteractive flag, show the resolved target, reject unsafe roots/symlinks, and document running-server behavior | P05, P07 | Avoid hangs and accidental recursive deletion |
| DEV-004 | Unknown commands and some operational failures can exit zero; several source call sites use undefined symbolic exit names | Define stable named nonzero usage/operational exit codes and deterministic aggregate status for bulk work | P14 | Automation must be able to detect failure |
| DEV-005 | Version behavior is supplied by sourced `.sh` files, with profiles only through Minecraft 1.7-era log formats | Encode profiles as inert Go data, retain the five legacy profiles, and add an explicitly tested modern profile; deprecated commands return capability errors where appropriate | P08 | Preserve legacy behavior without executing code and avoid false success on modern servers |
| DEV-006 | Self-update recursively downloads/replaces scripts and version files from the Bash project's update URL | Update only this fork's platform-specific Go release artifact after provenance verification, with atomic replacement and rollback | P15 | A compiled application cannot safely use the legacy script updater |
| DEV-007 | Live backup cleanup is process-local; interruption can leave saving disabled or publish partial archives | Use staged archives, durable pending-operation state, cleanup/recovery, and restore tests; disclose full-consistency limits for live plugin data | P10, P11 | A backup must be recoverable and must not endanger the live server |
| DEV-008 | RAM worlds default enabled and can treat an ordinary configured directory as a RAM disk | Default new installations to disabled, require explicit validated RAM-backed storage, preserve imported intent, and report durability limits | P12 | Avoid a misleading or unsafe default |
| DEV-009 | JAR-group rename leaves existing JAR symlinks pointing at the old path | Update affected references atomically or refuse the rename with actionable output | P07 | A reported-success rename must not break servers |
| DEV-010 | Log confirmation can match old/unrelated lines, and waits may be unbounded | Correlate from a fresh offset/event, model readiness separately from liveness, and enforce deadlines | P04, P06, P08 | Prevent false success and hung automation |
| DEV-011 | Complete backup symlink-following can capture data outside the managed server tree | Preserve the configuration option but preview/validate external targets and refuse unsafe or recursive capture by default | P03, P10 | Prevent unintended data disclosure and archive recursion |
| DEV-012 | Maintenance retention uses broad `find | xargs rm` pipelines | Implement scoped Go pruning with dry-run, root validation, locking, and recovery retention rules | P13 | Avoid unsafe deletion and shell dependencies |
| DEV-013 | `SCREEN_NAME` may be any string; it is interpolated into shell commands and matched by searching `ps ax` output | A session name must be 1–64 ASCII letters, digits, `_` or `-` (the default `msm-{SERVER_NAME}` always qualifies); sessions are addressed by exact `<pid>.<name>` and identified by the window process's argv and owner, not a substring search | P04 | `.` breaks screen's `<pid>.<name>` IDs, and a substring match can report or signal an unrelated process |
| DEV-014 | Console input is spliced into `screen -X eval 'stuff "..."'`, so quotes, `$`, `^` and `\` in a command are reinterpreted, and embedded newlines enter extra commands | Send exactly one line of at most 1000 bytes of printable UTF-8, escaped for screen's parser and delivered in bounded chunks; reject control characters | P04, P08 | Prevent command injection and silent truncation (screen drops an over-long `stuff` argument while exiting 0; macOS canonical tty lines stop at 1024 bytes) |
| DEV-015 | Root runs `console` through `su - <user>` and `script`, which allocates a terminal the server user owns | `console` runs only as the session owner; root is told to switch user first. Every other screen operation still runs as the owner from root, with credentials dropped for the child only | P04 | Avoid a shell/`script` dependency whose syntax differs between util-linux and macOS; upstream already documents that `su` consoles are unreliable |
| DEV-016 | `<server> config <key> <value>` (`command_server_config`) writes any value into `server.properties` with `sed`, so a value containing a line break adds or corrupts property lines | Refuse a property key or value containing CR, LF or NUL, and a key that is empty, padded, starts a comment or contains `=`; nothing is written | P03, P14 | A setting must not be able to inject another property, such as raising `op-permission-level` |
| DEV-017 | `server create` links the newest JAR from a `minecraft` JAR group when one exists, downloading it first through the unverified updater | `server create` makes the instance only; the administrator selects a JAR afterwards. P07 decides whether create selects a default group once downloads are verified | P05, P07 | Creating a directory must not start an unverified download or silently choose a JAR |
| DEV-018 | `server delete` stops a running server after confirmation, and running state comes from a `ps` substring search | `server delete` and `server rename` refuse any server not proven stopped (running, an unverified session with its screen name, or state that cannot be inspected); the administrator stops it first | P05 | A destructive command must not also be a stop command, or act on a guess about liveness |
| DEV-019 | Waiting for a server to stop is unbounded, a start reports "Done" whether or not the start line appeared, the global stop sends only `stop` (no `save-all`), per-server stop removes the active marker before the countdown (so Ctrl+C leaves a running server marked inactive), the global restart announces `RESTART_DELAY` but waits `STOP_DELAY`, and bulk commands run one server at a time | Readiness (a fresh start line) and stopping each have a deadline (default 5 minutes, or the profile's longer start timeout; `--timeout` overrides); at the deadline the command fails nonzero, says what is still running and never kills anything. Every stop, global or not, sends `save-all`, then `stop`, and waits. Intent changes when the operation commits: an aborted countdown leaves the server running and its intent unchanged. The global restart waits `RESTART_DELAY`. Bulk commands handle up to `--jobs` servers at once and fail with an aggregate status listing every failed server | P06 | Automation must see failure instead of a hang or a false success, and an interrupted stop must not silently change what `msm start` will do |
| DEV-020 | JAR group targets may be plain http URLs; `minecraft` targets need `jq`, `wget` and files in `/tmp`; delete removes a group servers still use; `<server> jar` overwrites whatever is at `JAR_PATH`, and selects the newest local JAR even when the download before it failed | Targets are an https URL, `minecraft` or `minecraft-snapshot`; http is refused when set and at download time. The aliases read Mojang's version manifest (v2) in Go and verify the version document and the server JAR against its SHA-1 and size. `jargroup delete` refuses a group any server's `JAR_PATH` points into and names those servers. `<server> jar` replaces `JAR_PATH` only when it is missing or a link (a JAR copied in by hand is left alone), and keeps the current JAR when the download fails | P07 | A server JAR must come from an authenticated source, and no JAR command may silently break or overwrite a server |
| DEV-021 | Console commands splice their arguments into the console line and into the confirmation regex, wait about one second, and print a success message whatever the server logged (a refusal, or nothing at all); a stopped server with `all` ends the script; `connected` answers with whatever matches a pattern that matches any line; `time`, `give` and the rest accept any word | Each argument must be one word (no spaces or control characters, at most 256 bytes) and is matched literally in the answer; a message is one printable line. A refusal in the log is an error naming the server's own words; an answer that never arrives is an error after 5 s (`--timeout` overrides) that says the command may still have taken effect; a command the version profile has no answer for is reported as *sent*, never as done. Answers must be log lines written after the command was sent, with a tag that cannot contain `]`, so chat cannot forge one. `all` skips servers that are not running with a note, and every other failure is reported together. `console` and `cmdlog` refuse `all`. Console and server log output has control characters removed | P08 | Prevent command injection, forged confirmations and false success (DEV-010) |
| DEV-022 | The shipped minecraft/1.3.0 patterns write literal parentheses as regex groups: `(ID <item>)`, `entered (<mode>)`, `(<time>)`, `(<amount>)`, so the server's own `(ID 1)` and `(9)` never match | The Go data escapes them; every profile inheriting 1.3.0 carries the fix, and a test shows the Go data equals the shipped files except for exactly these escapes | P08 | A confirmation that can never match makes a working command look unanswered |
| DEV-023 | Profiles stop at Minecraft 1.7; `toggledownfall` and `give`'s damage value, `gamemode` words and `xp` are sent as typed whatever the server version | The `minecraft/1.13.0` profile (Minecraft 1.13 and later, vanilla and Paper/Spigot wording; chosen only by `msm-version=minecraft/1.13` or later, so an unset VERSION keeps the 1.7 behavior) answers every command. `toggledownfall` and a `give` damage value fail before anything is sent, saying what to use instead (`cmd weather ...`). `gamemode` takes `survival`, `creative`, `adventure`, `spectator` or 0-3 and sends the form the version understands. `xp` is `experience add ... points`. Its log texts are written from the vanilla language file and tested against recorded lines, not yet against a live server (P16) | P08 | Let current servers work without pretending removed commands exist |
| DEV-024 | `worlds on`, `worlds off` and `worlds load` run whatever the server is doing; `worlds load` and server start prepare links with `rm -f`/`ln -s` through a shell, replace any file named like a world (`rm -f`), report a world they could not link and still exit zero, and create `worldstorage/<level-name>` even when the server directory already holds that world; `worlds on`/`off` move with `mv` (which fails across filesystems or nests into an existing directory); `worlds on all` is not accepted for one server | All four change a server only when it is proven stopped and hold its lock. Links are made with descriptor-relative calls, replaced atomically, and only over a symbolic link or nothing: a real file or directory is reported and kept, the other worlds are still linked, `worlds load` exits nonzero and start continues with the report. `<level-name>` is prepared only when no world of that name exists in the server directory or in inactive storage. A world that exists in both storage directories is ambiguous and is not linked, activated or deactivated. A move across filesystems is copy, publish, retire, remove, and never replaces anything. A world with a copy in RAM is not deactivated until synchronized. Names that are hidden, contain control characters or are symbolic links are not worlds. Deactivating removes the world's own link | P09 | A link or move must not destroy data, race a running server, or report success after a partial result |
| DEV-025 | World backups are made with `zip -rq`, which follows every symbolic link inside a world, so a link planted in a world copies whatever it points at into the archive, and a link back into the world loops | World archives store a symbolic link as a link (the target text, no content) and never follow one. A complete backup keeps `COMPLETE_BACKUP_FOLLOW_SYMLINKS` (DEV-011) | P10 | World archives must not capture data from outside the world or recurse |
| DEV-026 | `worlds backup` and `backup` do `save-off`, `save-all`, zip the live files, then `save-on`, and print `Done` whatever happened; a disabled or half-configured method (`WORLD_ARCHIVE_ENABLED=false`, rdiff-backup, rsync) is skipped silently; archives are created with the invoker's umask and an existing archive of the same second is overwritten by `zip` | A running server is saved with its version profile's commands, each confirmed from a fresh log line (the backup stops if one is refused or unanswered); a stable copy of the worlds (or server) is staged, saving is turned back on, and only then is the copy compressed. Saving is re-enabled on every error, on Ctrl+C or termination and on timeout; a `.msm-backup-pending` marker in the server directory lets the next backup re-enable it and remove staged leftovers if the manager was killed. Archives are written to a temporary name, re-read, and published with one link that never replaces an existing archive (a second archive in the same second gets `-1`, `-2`...); they are `0600`, their directories `0700`. A configuration that cannot be honoured (no method enabled, an invalid flag, a missing optional program, no active world) is an error, never a silent skip (see DEV-027 to DEV-029 for the rsync and rdiff-backup methods). A server not proven stopped and not reachable on its console is refused. A server that refuses `save-off` (it is already off) is left as it was | P10, P11 | A backup must be recoverable, must not leave the live server unsaved, and must not report success after a partial result. Full consistency of plugin and configuration files is claimed only for a stopped server |
| DEV-027 | `RSYNC_BACKUP_ENABLED` runs `rsync -aH --link-dest=<dir>/latest` through `sh -c` with the paths spliced in, builds the snapshot in place under its final name, replaces `latest` with `rm -f` then `ln -s`, and prints `Done` whatever happened | Hard-link snapshots are made in Go (no `rsync`, no shell) in the same layout, `<dir>/<timestamp>/<world>` and a relative `latest` link, built under a temporary name, verified, published with a rename that cannot replace a snapshot, and `latest` replaced atomically. Unchanged means same size, permission bits and mtime to the nanosecond; a link is never made to a different filesystem's file and falls back to copying; no file of an older snapshot is written through a shared inode. Not kept: owner and group (the backup runs as the server's owner), extended attributes and ACLs (`-aH` did not copy them either), and hard links inside a world (each name is its own file; `-H`). Links are stored as links; special files are skipped with a warning | P11 | The same recoverable snapshots without an external program, a shell, a half-published snapshot or a moment with no `latest` |
| DEV-028 | `RDIFF_BACKUP_ENABLED` runs `cd <dir> && nice -n <N> rdiff-backup <dir> <repo> && ... --remove-older-than <N>D --force` through `sh -c`, from the live world, with `RDIFF_BACKUP_ROTATION` and `RDIFF_BACKUP_NICE` unchecked, and prints `Done` whatever happened | `rdiff-backup` is run directly with an argument vector (under `nice` unless the priority is 0), with the command line its installed version has (the legacy one before 2.2, actions from 2.2); a running server is backed up from the staged copy; the program, its version and an existing repository are checked before the server is touched; the setting values are validated (rotation 1 to 36500 days, priority -20 to 19, negative only as root); the exit-2 "no increment is older than" result of retention is accepted; any other failure is reported. The program remains an external, non-Go dependency, and no other format is offered as rdiff compatible | P11 | Existing repositories keep working, a missing tool fails only the mode that needs it, and nothing is evaluated by a shell |
| DEV-029 | `WORLD_ARCHIVE_ENABLED`, `RDIFF_BACKUP_ENABLED` and `RSYNC_BACKUP_ENABLED` are compared with the string `true`; anything else (`yes`, `TRUE`, a typo) silently turns the method off | A value other than `true` or `false` is an invalid setting, and the backup does not start. With all three `false` nothing would be backed up, which is also an error | P11 | A backup that silently does not happen is worse than one that refuses |

## Decision rule

Compatibility means preserving user intent, data layout, and useful operational
semantics. It does not mean preserving shell injection, disabled certificate
checks, false-positive success, unbounded waits, unsafe recursive deletion, or
obsolete behavior that modern Minecraft explicitly rejects.
